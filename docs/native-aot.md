# Native AOT migration

## Serialization

Call `LibrarianJson.Register(MyContext.Default.MyDocument)` before any typed document operation. The context must be generated by System.Text.Json. Register each document type used by `BuildQueryable<T>`, typed index reads, and `LibrarianRepository<TDocument>`. Register enum and nullable enum contracts used directly as query values or projected scalar columns. Built-in primitives, dates, GUIDs, nullable scalars, and JsonElement have generated contracts. Include nested document types in your generated context as usual; nested deserialization uses that context.

Registration is process-wide, thread-safe, and idempotent for the same metadata instance. A conflicting contract throws. There is no implicit reflection serializer. A missing document registration throws before a query starts, rather than causing the scan to skip all documents. Repository diagnostic logging uses the registered serialization contract too.

Keep the persisted JSON schema compatible: remote property paths use `[JsonPropertyName]` or camelCase names. Generate web-style contracts with camelCase property naming, case-insensitive reads when needed, and `UseStringEnumConverter = true` to retain the previous string-enum behavior. Use generic `JsonStringEnumConverter<TEnum>` for custom enum converters. Custom converters and polymorphic subtypes must be explicitly supported by the generated context.

FileSystem uses its own generated context for the database envelope (`Dictionary<string, List<IdValuePair>>`); stored document JSON stays unchanged. Existing UTF-8 and BOM-detected UTF-16/32 files remain readable.

## Query execution

The providers no longer use `Activator`, `MakeGenericType`, `DynamicInvoke`, name-based expression method lookup, or `EnumerableQuery` rebinding. Generic query creation supplies precompiled result-list, default-value, comparer, and query factories. Non-generic `CreateQuery` can reuse known query element types; use generic `CreateQuery<T>` for a new type.

Expressions are interpreted with `Compile(preferInterpretation: true)`, so they require no runtime code generation. Expression trees still carry statically referenced member metadata; this is AOT-compatible metadata inspection, not a claim that every `System.Reflection` API is absent. Decimal operator metadata is explicitly preserved because the C# compiler emits unbound decimal expression operators that must be resolved while the caller constructs the tree. Captured fields/properties remain live, and auto-property detection prevents computed getters from becoming stale index keys.

The local indexed fast paths remain. The general local executor explicitly supports Where, Select (including indexed lambdas), OrderBy/ThenBy variants, Skip/Take with integer counts, Reverse, Concat, Cast/OfType, Distinct, SequenceEqual, Contains, Count/LongCount, Any/All, First/Single/Last variants, and numeric Sum/Average/Min/Max. Custom-comparer overloads and other operators are not supported. Use `AsEnumerable()` before additional client-side operations. Unsupported operators throw instead of silently falling back to runtime-generated generic LINQ code. Interpreted residual expressions may be slower than JIT-compiled expressions; indexed filtering and paging still limit materialization.

Remote SQL/Redis query restrictions otherwise remain. Default-comparer and ordinal string HashSet membership uses typed factories; custom element types must be registered. C# 14 array Contains calls are normalized before local interpretation because the interpreter cannot box spans. Other ref-struct expressions are not supported.

Prefer named record constructors or scalar projections in applications that treat trimming warnings as errors. C# emits calls to trimming-annotated Expression APIs for anonymous projections and property member initializers; these can require explicitly preserving projection metadata in the application. The library cannot suppress or solve warnings emitted by consumer code. The native smoke test uses record and scalar projections.

## Verification

```sh
dotnet publish test/Soenneker.Librarian.NativeAot.Smoke -c Release -r win-x64 -o artifacts/native-aot -p:TreatWarningsAsErrors=true -p:IlcTreatWarningsAsErrors=true
./artifacts/native-aot/Soenneker.Librarian.NativeAot.Smoke.exe
```

On Linux use `linux-x64` and omit `.exe`. The host needs the native compiler toolchain. The executable checks memory queries, filesystem save/reload, generated serialization, closures, ordering, projections, aggregates, and remote translation/materialization. Set `LIBRARIAN_TEST_REDIS` and `LIBRARIAN_TEST_POSTGRES` to exercise remote I/O as well. CI supplies disposable services for those checks. No runtime servers are started by the smoke executable.
